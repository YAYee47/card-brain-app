# Card Brain (多軌極速記帳) - 開發筆記

這份筆記記錄了本專案的核心開發歷程、架構設計思路，以及重要的優化迭代，方便未來維護與擴充。

## 1. 核心業務邏輯與架構
本專案分為 **前端 (Mobile App)** 與 **後端 (API Server)** 兩個主要部分：
- **前端 (React Native + Expo)**：專注於流暢的使用者體驗 (UX)，包含相機呼叫、圖片上傳、表單狀態管理以及動畫互動。
- **後端 (FastAPI + Python)**：負責繁重的運算，包含 AI 視覺辨識 (OCR)、信用卡權益推薦引擎、網頁爬蟲與 SQLite 關聯式資料庫管理。

## 2. 關鍵功能實作紀錄

### 💡 雙軌記帳與 AI 收據辨識 (`ocr.py`)
- **痛點**：手動記帳太慢，且使用者常常記不得刷哪張卡最划算。
- **解法**：整合 Google Generative AI (Gemini Flash 模型)。使用者上傳實體發票照片或數位載具截圖後，後端透過 Prompt 將圖片轉換為結構化的 JSON 資料（包含：消費金額、幣別、商家名稱、日期等）。
- **UX 設計**：前端移除了繁雜的 QR Code 掃描，提供直覺的「AI 收據辨識」與「手動記帳」兩個入口，在操作語意上給予使用者更清晰的情境暗示。

### 🧠 智慧推薦引擎 (`recommend.py`)
- **痛點**：各家銀行的權益條款複雜（如：玉山 Unicard 的百大特店、星展的特定加碼）。
- **解法**：建立動態推薦引擎。
  - **智慧字典 (Smart Dictionary)**：將使用者輸入的自由文字（如：`全聯`、`星巴克`、`7-11`）自動映射到權益分類（如：`超市`、`餐飲`、`超商`）。
  - **百大特店比對**：導入本地 `unicard_merchants.json` 名單，精準判斷如「台灣虎航」等特店。
  - **客製化過濾**：根據使用者狀態（如：是否為新戶、是否為大戶等級），在計算回饋時動態排除不適用的加碼權益。

### 📊 額度分離架構與進度條計算 (`transactions.py`, `dashboard.py` & `monthly_usage.py`)
- **核心重構**：過去將 `MonthlyUsage` 綁定在整張卡片上，導致一般消費會錯誤擠壓特定通路的加碼額度（例如吉鶴卡國內消費會扣到日系名店額度）。系統已完成核心重構，加入 `card_benefit_id`，實現「每一條權益獨立計算額度」，徹底解決額度互相排擠的 Bug。
- **修正重點**：原本系統誤將「回饋金上限 (Cap)」直接當作「消費上限」來顯示。
- **計算邏輯**：系統改為透過 `回饋金上限 ÷ 加碼趴數` 來反推真實的「消費額度上限 (Spend Cap)」。進度條 (`benefit_usages`) 現已能準確反映當前花費佔「總可刷額度」的比例，避免記帳小額卻提早封頂的錯誤顯示。

### 🕷️ 自動化爬蟲與排程 (`scheduler.py`)
- **設計**：為了保持信用卡權益資料庫的最新狀態，我們實作了爬蟲腳本定期去抓取銀行官網。
- **優化**：為避免過度頻繁打擾目標網站，排程從每月執行調整為「每季初 (1, 4, 7, 10 月)」自動執行更新。

## 3. UI/UX 介面演進
- **從「點擊」到「智慧輸入」**：捨棄了早期冗長的「支付通道」橫向按鈕列，改為類似 Google 搜尋的單一輸入框 `(如：星巴克、LINE Pay)`。結合後端的智慧字典，大幅降低了使用者的認知負擔。
- **原生體驗強化與 Debug**：
  - 導入了 `@react-native-community/datetimepicker` 替換手動輸入日期的痛點，提供系統原生的日曆選單。
  - 期間曾遇到 iOS 14+ 傳遞不支援的 `textColor` 導致 React Native 底層 LogBox 迭代觸發 `PushNotificationIOS` 崩潰的問題，最終透過只保留 `themeVariant="light"` 成功鎖定淺色黑字，解決了深色模式下字體不可見的狀況。
  - 幣別選擇從按鈕循環切換，升級為底部的半透明 Modal 彈出選單，使介面更加統一且具質感。

## 4. 未來擴展方向
- **支援更多信用卡**：擴充爬蟲腳本以支援國泰世華、台新等更多主流銀行卡片。
- **AI 自動記帳分類**：透過 AI 判斷消費類別，進一步生成每月的消費圓餅圖分析。
