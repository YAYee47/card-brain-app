# Card Brain 程式碼架構導覽

這是一份給您的「地圖」，幫助您快速了解專案中每一個檔案與資料夾負責的工作。專案主要分為 **後端 (backend)** 與 **前端 (mobile)** 兩大區塊。

---

## 💻 後端 (Backend) - FastAPI + Python

後端是整個系統的大腦，負責所有複雜的運算、資料庫存取與 AI 串接。

### 📌 核心設定 (`backend/app/`)
- **`main.py`**：後端程式的**總入口點**。負責啟動 FastAPI 伺服器、設定跨域請求 (CORS)，並且把所有零散的 API 路由 (Router) 註冊進來。
- **`db/database.py`**：負責連線到 SQLite 資料庫 (`card_brain.db`) 的設定檔。

### 📌 API 進入點 (`backend/app/api/v1/endpoints/`)
這些檔案定義了前端可以呼叫的網址 (URL) 路徑：
- **`transactions.py`**：處理「記帳」相關的請求。包含前端上傳截圖/收據時，呼叫 AI 的入口，以及將最終記帳結果存入資料庫的路由。
- **`recommend.py`**：處理「權益推薦」的請求。接收前端傳來的消費通路與金額，並回傳排序好的最優卡片列表。
- **`dashboard.py`**：處理「儀表板」的請求。負責將首頁需要的各張卡片進度條、累積回饋等資訊打包傳給前端。
- **`cards.py`**：處理「卡片管理」的請求。列出系統擁有的所有卡片，以及使用者勾選「已擁有」卡片的邏輯。
- **`users.py`**：處理「使用者登入與註冊」的請求。實作了基於 UUID 的設備綁定與原生 `bcrypt` 的密碼安全雜湊 (Password Hash) 防護機制。

### 📌 核心服務邏輯 (`backend/app/services/`)
這裡是系統真正運作「商業邏輯」的地方，也是這幾天我們改動最多的地方：
- **`recommend.py`**：**【核心引擎】** 負責執行複雜的比對邏輯。我們寫的「台灣常見場景智慧字典」與「百大特店模糊比對」都寫在這裡。它會計算每張卡的 Base/Bonus 趴數是否達上限，最後算出預估回饋金。
- **`ocr.py`**：**【AI 辨識】** 負責與 Google Gemini AI (Flash 模型) 溝通。它會接收圖片，並下 Prompt 告訴 AI 該如何萃取出消費金額、日期與商家名稱。
- **`dashboard.py`**：負責幫首頁「算數學」。計算這個月已經花了多少錢、佔了額度上限的百分之多少，產生進度條的資料。
- **`scheduler.py`**：**【排程器】** 我們設定好的爬蟲定時器。它會每季自動喚醒底下的爬蟲程式去更新資料庫。
- **`crawler_*.py`**：各家銀行信用卡的爬蟲腳本（如玉山 Unicard 等），負責去官方網站抓取最新權益。

### 📌 資料結構定義
- **`models/*.py`**：SQLAlchemy **資料庫表格 (Table)** 的定義。裡面規定了哪些欄位是字串、整數，以及誰關聯誰（如 User 關聯 Card）。
- **`schemas/*.py`**：Pydantic **資料格式驗證 (Type)**。負責檢查前端傳進來的 JSON 資料格式對不對、後端吐出去的資料該長什麼樣子。

### 📌 自動化單元測試 (`backend/tests/`)
所有後端核心業務邏輯皆已編寫完整的自動化單元測試，確保更動程式碼時不會發生回歸錯誤 (Regression)：
- **`test_transactions.py`**：測試記帳回饋精算（如 Lakole 嚴選日系名店 4%、App Store 9%、加碼上限扣打消耗等）。
- **`test_unicard.py`**：測試玉山 Unicard 的「簡單選 / 任意選 / UP選」方案切換與回饋判定。
- **`test_recommend_service.py` & `test_recommend_endpoint.py`**：測試各通路的最佳卡片推薦演算法與需登錄/不需登錄的排序邏輯。
- **`test_billing_cycle.py`**：測試每張卡片 1~31 號帳單結帳週期的精準換算。
- **`test_alerts_service.py`**：測試 80% 額度預警與 100% 封頂警報通知生成。
- **`test_ocr.py`**：測試 Google Gemini Vision OCR 辨識介面與防呆處理。
- **`test_crawler.py`**：測試銀行權益爬蟲與自動差異比對引擎。

執行測試指令：
```bash
cd backend
pytest tests/
```

## 📱 前端 (Mobile) - React Native + Expo

前端是使用者的操作介面，負責呈現漂亮的畫面並將使用者的操作轉化為 API 請求送給後端。

### 📌 畫面佈局 (`mobile/app/(tabs)/`)
這裡的每個 `.tsx` 檔案都對應到底下導覽列的一個分頁 (Tab)：
- **`index.tsx` (首頁/儀表板)**：負責顯示「當月總消費」與各張卡片的「回饋進度條」。它會呼叫後端的 `dashboard.py` 取得數據。
- **`scan.tsx` (記帳頁)**：**【最複雜的頁面】** 我們剛剛改造的頁面。裡面包含呼叫手機相機/相簿的邏輯、跳出「智慧文字輸入框」與「原生日期小日曆」的介面，最後把表單送出給後端記帳。
- **`recommend.tsx` (推薦頁)**：獨立的消費試算頁面。當您還沒要花錢，只是想查「買機票刷哪張好」時使用的介面。
- **`cards.tsx` (卡片管理)**：讓您打勾選擇自己錢包裡目前有哪些信用卡的設定頁。

### 📌 API 串接 (`mobile/src/api/`)
這裡的檔案就像是「外送員」，負責把前端畫面的需求，透過網路送去給後端：
- **`client.ts`**：負責基礎的網路設定，把 `EXPO_PUBLIC_API_URL` (也就是您電腦的區網 IP) 設定好。
- **`transactions.ts`**：負責把圖片轉換成 FormData 送去給後端做 AI 辨識，以及送出記帳表單。
- **`recommend.ts`**：負責打給後端要推薦卡片的列表。
- **`cards.ts`**：負責向後端請求系統信用卡清單與更新使用者擁有的卡片。
